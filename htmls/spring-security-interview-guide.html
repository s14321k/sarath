How Auto-Configuration works ▼

@EnableAutoConfiguration triggers Spring Boot to scan META-INF/spring/...AutoConfiguration.imports across all JARs on the classpath. Each auto-configuration class uses conditional annotations to decide whether to register its beans.

@Configuration @ConditionalOnClass(DataSource.class) // only if class exists on classpath @ConditionalOnProperty(name = "spring.datasource.url") // only if property set public class DataSourceAutoConfiguration { @Bean @ConditionalOnMissingBean // only if user didn't define one DataSource dataSource() { ... } }
ConditionalWhen it applies
@ConditionalOnClassClass is on classpath
@ConditionalOnMissingBeanUser hasn't defined that bean
@ConditionalOnPropertyProperty exists in config
@ConditionalOnWebApplicationApp is a web application
@Profile("dev")Specific profile is active
🎭
Spring Profiles ▼

Profiles allow different configurations for different environments.

// Different datasource per environment @Bean @Profile("dev") public DataSource devDataSource() { return new EmbeddedDatabaseBuilder().setType(H2).build(); } @Bean @Profile("prod") public DataSource prodDataSource() { return DataSourceBuilder.create().url("jdbc:postgresql://...").build(); }

Activate via: spring.profiles.active=prod in properties or --spring.profiles.active=prod CLI flag.

Name convention: application-dev.yml, application-prod.yml — loaded automatically for that profile.

Types of Dependency Injection Must know ▼
✅ Constructor (Recommended)

Dependencies injected via constructor. Immutable fields. Spring team's recommendation.

✔ Explicit dependencies

✔ Supports final fields

✔ Easy to test (no Spring needed)

⚠️ Setter Injection

Dependencies set after construction. Useful for optional dependencies only.

⚠ Can result in partially configured objects

⚠ Not immutable

❌ Field Injection

@Autowired on field. Short but hides dependencies — discouraged in production.

✗ Hidden dependencies

✗ Hard to test

✗ Breaks immutability

// ✅ Constructor injection — RECOMMENDED @Service public class OrderService { private final PaymentService paymentService; public OrderService(PaymentService paymentService) { this.paymentService = paymentService; // @Autowired optional since Spring 4.3 } }

Circular Dependencies — causes, detection, fixes ▼

Occurs when Bean A → needs Bean B → needs Bean A. Spring 2.6+ disallows this by default.

// ❌ Circular — BeanCurrentlyInCreationException @Service class A { final B b; A(B b) { this.b = b; } } @Service class B { final A a; B(A a) { this.a = a; } }
✅ Best Fix

Refactor: extract shared logic into a 3rd class C. Both A and B depend on C.

⚠️ Workaround

Use @Lazy on one injection — defers creation until first access.

❌ Avoid

spring.main.allow-circular-references=true — hides bad design.

CSRF protection ▼

CSRF tricks a logged-in user's browser into making unwanted requests to another site. Protection: server generates a unique token per session; client must include it in state-changing requests.

// Spring Security — cookie-based CSRF token csrf -> csrf.csrfTokenRepository(CookieCsrfTokenRepository.withHttpOnlyFalse()) // Sets XSRF-TOKEN cookie (readable by JS) // Frontend sends it back as X-XSRF-TOKEN header

Additional protections: SameSite=Strict cookies Origin/Referer header checks

JWT & OAuth2
Token structure · OAuth2 flows · OIDC · SSO
🎟️
JWT — structure & how it works Frequent ▼

JWT = Header.Payload.Signature — a compact, signed, self-contained token.

// Decoded JWT payload example { "sub": "user123", "email": "john@example.com", "roles": ["ADMIN"], "iss": "https://auth.example.com", // issuer "aud": "spring-boot-api", // audience "iat": 1699990000, // issued at "exp": 1699993600 // expires at }
💡 JWT = token format. OAuth2 = authorization framework. They work together but are different things.
Security best practices

✔ Short-lived access tokens (5–15 min)

✔ Refresh tokens for long sessions

✔ HttpOnly cookies (not localStorage)

✔ Always use HTTPS

✔ Validate signature + exp + iss + aud

Token types

ID Token — who the user is (OIDC)

Access Token — what they can do (scopes/roles)

Refresh Token — silently get new access token

🔄
OAuth2 Authorization Code Flow ▼
1
Client redirects to IdP /authorize
With client_id, redirect_uri, scope, code_challenge (PKCE)
2
User logs in & approves
IdP shows login page, user submits credentials (+ MFA)
3
IdP redirects with authorization code
Short-lived, one-time code sent to redirect_uri
4
Client exchanges code for tokens
POST to /token with code + code_verifier (PKCE)
5
IdP returns ID token + Access token
Client stores in memory (not localStorage)
6
Client calls Spring Boot API
Authorization: Bearer <access_token>
7
Spring Security validates JWT
Verifies signature via JWKS, checks exp/iss/aud

@Transactional — propagation & gotchas ▼
PropagationBehavior
REQUIRED (default)Join existing tx; create new if none exists
REQUIRES_NEWAlways create new tx; suspend existing
SUPPORTSUse tx if exists; proceed without if none
NOT_SUPPORTEDAlways proceed without transaction
⚠️ Self-invocation problem: If you call a @Transactional method from within the same class, the proxy is bypassed and the transaction annotation is ignored. Always call through the Spring proxy (inject self or refactor to separate class).

AOP — Aspect-Oriented Programming
Cross-cutting concerns · Advice types · Custom annotations
🎯
What is AOP and why use it? ▼

AOP separates cross-cutting concerns (logging, security, transactions, retry) from business logic. Instead of duplicating code in every method, write one Aspect class that intercepts method calls.

Without AOP ❌

Logging in every service method. Exception handling duplicated. Transaction boilerplate everywhere.

With AOP ✅

One aspect class handles logging for all methods. Business code stays clean. Add cross-cutting logic without touching business code.

AOP terminology
TermMeaning
AspectModule containing cross-cutting concern
AdviceCode that runs at a join point (Before, After, Around)
Join PointPoint in execution (method call) where advice applies
PointcutExpression to match join points
WeavingApplying aspect to target object (Spring uses proxy-based)
💻
Logging aspect — full example ▼
@Aspect @Component public class LoggingAspect { private static final Logger log = LoggerFactory.getLogger(LoggingAspect.class); // Pointcut: all methods in service package @Pointcut("execution(* com.example.service.*.*(..))") public void serviceMethods() {} // Runs BEFORE method @Before("serviceMethods()") public void logBefore(JoinPoint jp) { log.info("Calling: {}", jp.getSignature().getName()); } // Runs AFTER successful return @AfterReturning(pointcut = "serviceMethods()", returning = "result") public void logReturn(Object result) { log.info("Returned: {}", result); } // Runs AROUND — full control @Around("serviceMethods()") public Object logTiming(ProceedingJoinPoint pjp) throws Throwable { long start = System.currentTimeMillis(); Object result = pjp.proceed(); log.info("Took: {}ms", System.currentTimeMillis() - start); return result; } // Runs if exception thrown @AfterThrowing(pointcut = "serviceMethods()", throwing = "ex") public void logException(Throwable ex) { log.error("Exception: {}", ex.getMessage()); } }
✨
Custom annotation + retry aspect ▼
// 1. Define custom annotation @Target(ElementType.METHOD) @Retention(RetentionPolicy.RUNTIME) public @interface Retryable { int attempts() default 3; } // 2. Aspect that intercepts @Retryable methods @Aspect @Component public class RetryAspect { @Around("@annotation(retryable)") public Object retry(ProceedingJoinPoint pjp, Retryable retryable) throws Throwable { int max = retryable.attempts(); Throwable last = null; for (int i = 0; i < max; i++) { try { return pjp.proceed(); } catch (Throwable t) { last = t; } } throw last; } } // 3. Usage — annotate any method @Retryable(attempts = 3) public String callExternalService() { ... }

Resilient service with fallback ▼
@Service public class ExternalApiService { @Retry(name = "todos-api") @CircuitBreaker(name = "todos-api", fallbackMethod = "fallback") @RateLimiter(name = "todos-api") @Bulkhead(name = "todos-api", type = Bulkhead.Type.SEMAPHORE) public Todo getTodo(Integer id) { return todoClient.getTodoById(id); // may fail } // Fallback — same signature + Throwable param private Todo fallback(Integer id, Throwable t) { log.warn("Fallback triggered: {}", t.getMessage()); return new Todo(id, "Default response", false); // or return cached data } }

CORS configuration ▼

CORS is required when frontend and backend are on different origins. The browser blocks requests unless the backend explicitly allows them.

@Configuration public class CorsConfig { @Bean public CorsFilter corsFilter() { UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource(); CorsConfiguration config = new CorsConfiguration(); config.setAllowedOrigins(List.of("https://frontend.com")); // never "*" with cookies config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE")); config.setAllowedHeaders(List.of("Authorization", "Content-Type", "X-XSRF-TOKEN")); config.setAllowCredentials(true); // required for cookies to pass through source.registerCorsConfiguration("/**", config); return new CorsFilter(source); } }

Spring Boot core (Q1–Q10) ▼
Q1 What is Spring Boot and why use it?
Spring Boot removes the boilerplate of Spring configuration. It provides auto-configuration, embedded servers (Tomcat/Jetty), starter dependencies, and production-ready features (Actuator). Allows you to create production-grade apps with minimal setup.
Q2 What's the difference between @SpringBootApplication and its components?
@SpringBootApplication = @Configuration + @EnableAutoConfiguration + @ComponentScan. It's a convenience annotation for the main class. You rarely split them — but you can to fine-tune scanning or disable auto-configuration selectively.
Q3 How does Spring Boot auto-configuration work?
@EnableAutoConfiguration loads all configuration classes listed in META-INF/spring/*.AutoConfiguration.imports. Each class uses @Conditional annotations to decide if it should create beans. Example: if spring-web is on classpath and no DispatcherServlet bean is defined, Spring Boot creates one.
Q4 What are Spring Starters?
Starters are pre-packaged dependency descriptors that bundle compatible libraries. spring-boot-starter-web brings Spring MVC + Tomcat + Jackson. spring-boot-starter-data-jpa brings Hibernate + Spring Data JPA + JDBC. No more hunting for compatible versions.
Q5 What is Spring Actuator?
Actuator adds production-ready endpoints: /health (app health), /metrics (CPU, memory, HTTP counts), /info (build info), /env (properties). Integrates with Prometheus/Grafana. Add spring-boot-starter-actuator to enable.
Q6 Which DI type should you prefer and why?
Constructor injection. It makes dependencies explicit, allows final fields (immutability), makes testing easy (no Spring needed in unit tests), and the Spring team recommends it. Field injection (@Autowired on field) hides dependencies and makes testing harder.
Q7 How do you handle circular dependencies?
Best fix: refactor — extract shared logic into a 3rd class. Quick fix: add @Lazy on one injection to defer creation. Avoid enabling spring.main.allow-circular-references=true as it hides design issues. Spring Boot 2.6+ disallows them by default.
Q8 What is the bean lifecycle?
Instantiation → DI → @PostConstruct → ready for use → @PreDestroy → destroyed. You can hook in via @PostConstruct/@PreDestroy, or implement InitializingBean/DisposableBean. BeanPostProcessor can intercept all beans before/after initialization.
Q9 When would you use @Scope("prototype")?
When a bean holds state that must be unique per use — e.g., per-user shopping cart, per-thread request state, mutable command objects. Default singleton shares one instance so mutable state causes race conditions.
Q10 What does @Transactional do and what are common pitfalls?
Wraps a method in a DB transaction — auto commits on success, rolls back on RuntimeException. Pitfall: self-invocation bypasses the proxy so the annotation is ignored. Always inject and call through the Spring proxy (or use another bean). Also: readOnly=true improves read performance by skipping dirty checking.

Security & Auth (Q11–Q20) ▼
Q11 JWT vs session-based authentication — key differences?
JWT is stateless — server stores nothing, validates token signature on each request. Session-based stores session in server memory/Redis, requires sticky sessions or shared session store. JWT scales better for microservices. Session is simpler for traditional monolith.
Q12 What's the difference between OAuth2 and OIDC?
OAuth2 = authorization framework (can this app access your data?). OIDC (OpenID Connect) = authentication layer on top of OAuth2 (who is the user?). OIDC adds an ID Token (JWT) that contains user identity. For login, use OAuth2 + OIDC. For API access delegation only, OAuth2 alone is fine.
Q13 What is CSRF and how do you prevent it?
CSRF tricks a logged-in user's browser into making unwanted requests. Prevention: CSRF token (server-generated, verified per request), SameSite=Strict cookies, Origin/Referer header validation. For REST APIs with JWT in headers (not cookies), CSRF is not a concern since cookies aren't automatically sent.
Q14 Where should you store JWT — localStorage or HttpOnly cookie?
HttpOnly cookie is safer. localStorage is vulnerable to XSS — any injected script can steal the token. HttpOnly cookies can't be read by JavaScript. Pair with SameSite=Strict for CSRF protection. Trade-off: HttpOnly cookies need CORS configured with credentials.
Q15 How do microservices propagate user identity?
Two options: (1) JWT propagation — pass the client's JWT downstream in Authorization header; each service validates it. (2) Token exchange — service A gets a new token scoped to service B (OAuth2 On-Behalf-Of). Combine with mTLS for transport security. Service mesh (Istio) can automate both.
Q16 What is LDAP and how does it relate to Spring Security?
LDAP is a directory protocol for storing users/groups (like Active Directory). Modern best practice: let an IdP (Keycloak, ADFS, Auth0) authenticate against LDAP, then issue JWTs. Spring Boot validates only the JWT — never queries LDAP directly. Direct Spring LDAP integration is legacy and lacks SSO/MFA/token benefits.
Q17 What is mTLS and when do you use it?
Mutual TLS — both client and server present certificates to authenticate each other, not just server to client. Used for service-to-service security in microservices. Service mesh (Istio) can enforce it automatically across all pods without code changes.
Q18 What does @PreAuthorize do vs @Secured?
@PreAuthorize supports full SpEL expressions: hasRole('ADMIN'), #userId == authentication.principal.id (resource ownership). @Secured only supports role-based checks: @Secured("ROLE_ADMIN"). Prefer @PreAuthorize for flexibility. Enable via @EnableGlobalMethodSecurity(prePostEnabled=true).
Q19 How do you configure Spring as an OAuth2 Resource Server?
Add spring-boot-starter-oauth2-resource-server. Set spring.security.oauth2.resourceserver.jwt.issuer-uri to your IdP. Spring auto-fetches JWKS and validates every incoming Bearer token. Spring Security populates the SecurityContext with claims from the JWT.
Q20 What are the best practices for API security?
Always HTTPS. Use OAuth2+OIDC+JWT. Short-lived access tokens (5-15 min). Validate JWT signature + exp + iss + aud. Rate limiting at API Gateway. Never store secrets in code (use Vault). HttpOnly + Secure + SameSite cookies for browser clients. Input validation on all endpoints.

JPA & Performance (Q21–Q30) ▼
Q21 What is the N+1 problem in JPA?
Loading a list of entities (1 query), then lazily loading their associations one-by-one (N queries). Fix: use JOIN FETCH in JPQL, @EntityGraph, or @BatchSize. Never loop and call a lazy collection getter — it fires N separate SQL statements.
Q22 persist() vs merge() in JPA?
persist() — for NEW entities only. Makes entity managed and schedules INSERT. Returns void. merge() — for DETACHED or EXISTING entities. Returns a NEW managed copy (always use the returned value, not the original). Calling merge() on a transient entity creates a new persisted copy.
Q23 Page vs Slice in Spring Data pagination?
Page runs two queries — one for data (LIMIT/OFFSET) and one COUNT(*) for total pages. Slice skips the COUNT query — just fetches data + checks if next page exists. Use Slice for infinite scroll or "Load More" patterns where total count isn't needed.
Q24 How do you implement auditing in JPA?
Enable @EnableJpaAuditing. Add @EntityListeners(AuditingEntityListener.class) to entity. Use @CreatedDate, @LastModifiedDate, @CreatedBy, @LastModifiedBy on fields. Implement AuditorAware bean to provide current user from SecurityContext.
Q25 What is optimistic locking and how to implement it?
Prevents lost updates in concurrent scenarios. Add @Version field to entity — JPA checks version matches before UPDATE. If two users read version 5 and both try to update, second one gets OptimisticLockException. Combine with ETag header for REST APIs.
Q26 What is @Cacheable and when should you use it?
Caches method return value. On first call, executes method and stores result. On subsequent calls with same key, returns cached value without executing method. Use for read-heavy, expensive, infrequently changing data (e.g., product catalog, config). Don't cache mutable or user-specific data without careful key design.
Q27 What is AOP and what are common use cases?
Aspect-Oriented Programming separates cross-cutting concerns from business logic. Common uses: logging, performance timing, transactions (@Transactional IS AOP), security (@PreAuthorize), retry logic, distributed tracing. Spring uses proxy-based AOP — aspects only work on Spring-managed beans called through the proxy.
Q28 @Before vs @Around advice — when to use each?
@Before — runs before method, cannot change result or prevent execution. @After — runs after regardless of outcome. @AfterReturning — only after success, can see result. @AfterThrowing — only after exception. @Around — full control: can modify args, prevent execution, change result, measure time. Use @Around for timing, retry, caching.
Q29 How does Circuit Breaker prevent cascading failures?
When too many calls to a service fail (e.g., 50% failure rate), Circuit Breaker opens — subsequent calls are immediately rejected without trying the service. After a wait period (e.g., 30s), it enters half-open state and tests recovery. This prevents the caller from wasting threads waiting on a dead service and cascading failure across the system.
Q30 What's the self-invocation problem with @Transactional?
If you call a @Transactional method from within the same class (this.method()), the call bypasses the Spring AOP proxy. The annotation is completely ignored — no transaction is created. Fix: inject the bean into itself (@Autowired @Lazy private MyService self), use a separate service class, or use TransactionTemplate for programmatic control.
