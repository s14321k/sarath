02

Main Features of Java

Platform Independent

Write once, run anywhere. Bytecode + JVM abstracts the OS.

Object Oriented

Abstraction, Encapsulation, Inheritance, Polymorphism — the four pillars.

Robust

Exception handling, strong type checking, no pointer arithmetic.

Multithreaded

Built-in support for multiple threads running simultaneously.

Secure

Runs inside JVM sandbox, no explicit pointers, bytecode verification.

High Performance

JIT compiler converts hot bytecode to native machine code at runtime.

Dynamic

Supports dynamic loading of classes (reflection, class loaders).

Simple

No pointers, no operator overloading, garbage collected — cleaner than C++.

JVM Memory Areas

Memory AreaDescriptionThread
HeapStores objects and instance variablesShared
StackStores local variables and method call framesPer Thread
Method Area / MetaspaceClass structure, method bytecode, static variablesShared
PC RegisterTracks current executing instructionPer Thread
Native Method StackExecutes native (non-Java) methods via JNIPer Thread

Heap Structure

Young Generation

Eden + Survivor S0/S1 spaces. New objects land in Eden. Minor GC runs here frequently and fast.

Old Generation

Long-lived objects promoted from Young. Major GC runs here, slower. Default ~⅔ of heap.

Metaspace (Java 8+)

Replaced PermGen. Stores class metadata. Grows dynamically in native memory — no more PermGen OOM.

⚠️
StackOverflowError occurs when the stack runs out — usually from infinite recursion. OutOfMemoryError from the heap. Know the difference!
04

JIT Compiler

JIT (Just-In-Time) is part of the JVM. Instead of interpreting bytecode line-by-line (slow), it compiles frequently executed ("hot") code segments into native machine code and caches them.

Client Compiler (C1)

Fast startup, light optimizations. Good for short-lived applications.

Server Compiler (C2)

Deeper optimizations (inlining, escape analysis). Better peak throughput.

Tiered Compilation

Default since Java 8. Starts with C1, promotes hot methods to C2. Best of both.

Java — Type Casting
// Widening — byte → short → int → long → float → double
int a = 10;
double b = a;  // automatic

// Narrowing — manual, may lose precision
double x = 12.5;
int y = (int) x;  // result: 12 (decimal lost)

// Upcasting — safe, automatic
Animal anim = new Dog();  // upcasting
anim.sound();  // calls Dog's method — runtime polymorphism

// Downcasting — explicit, use instanceof first
if (anim instanceof Dog) {
    Dog d = (Dog) anim;  // safe downcast
}

// Java 16+ pattern matching for instanceof
if (anim instanceof Dog dog) {
    dog.fetch();  // no explicit cast needed!
}

OOP Concepts

Polymorphism

📌
Overriding rules: private, static, final methods cannot be overridden. Access modifier can be widened but not narrowed. Always use @Override — catches typos at compile time. All non-static, non-final, non-private methods in Java are virtual by default.

Encapsulation

Hide data using private fields + public getters/setters. Protects object integrity and allows validation logic in setters.

Inheritance

Child class inherits from parent using extends. Java does not support multiple class inheritance to avoid the diamond problem. Prefer composition over inheritance — "has-a" is usually more flexible than "is-a".

Cohesion vs Coupling

High Cohesion ✓ Good

A class does one thing well. All methods and fields relate to a single responsibility. Follows SRP (Single Responsibility Principle).

Loose Coupling ✓ Good

Classes depend on each other minimally — via interfaces, not concrete classes. Easy to test and swap implementations.

Tight Coupling ✗ Bad

Classes are highly interdependent. Changing one breaks others. Hard to test in isolation. Avoid.

Java — String Pool
String a = "Hello";               // String Pool
String b = new String("Hello");  // Heap — new object
String c = "Hello";               // String Pool — reuses 'a'

a == b          // false  — different references
a == c          // true   — same pool reference
a.equals(b)     // true   — same content
b.intern() == a // true   — intern() adds to pool
💡
Why String is immutable? Multiple references can point to same pool String. If mutable, one reference changing it affects all. Also needed for safe HashMap keys (hashCode must not change) and security (class names, file paths).

Multithreading

Thread Lifecycle

New

Thread object created but start() not called yet.

Runnable

Ready to run or currently running. Scheduler picks from here.

Blocked / Waiting

Waiting for lock (Blocked) or waiting for signal (Waiting).

Timed Waiting

Waiting for fixed duration — sleep(), join(timeout).

Terminated

Thread completed run() or stopped abnormally.

Java — Thread Creation Methods
// Method 1: Extend Thread
class MyThread extends Thread {
    public void run() { System.out.println("Running..."); }
}
new MyThread().start();

// Method 2: Implement Runnable (preferred — keeps class free to extend)
new Thread(() -> System.out.println("Lambda task")).start();

// Method 3: ExecutorService (production standard)
ExecutorService executor = Executors.newFixedThreadPool(5);
Future<Integer> result = executor.submit(() -> 42);  // Callable
executor.shutdown();

HashMap Internal Working

🔑
1. Key → hashCode() → bucket index (hash & (n-1))
2. Bucket empty → insert node
3. Collision → LinkedList (or Red-Black Tree if bucket size ≥ 8 AND capacity ≥ 64)
4. Uses equals() to check duplicate key
5. Default capacity = 16, load factor = 0.75, resizes when size > 12
6. Tree back to LinkedList when bucket shrinks below 6

Serialization

Converting object to byte stream for storage/transmission. Class must implement Serializable. transient fields are skipped.

Java — Serialization
class Employee implements Serializable {
    private static final long serialVersionUID = 1L;  // version control
    String name;
    transient int salary;  // NOT serialized
    static String company;  // NOT serialized (static)
}

// Serialize
try (ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("emp.ser"))) {
    oos.writeObject(emp);
}

// Deserialize
try (ObjectInputStream ois = new ObjectInputStream(new FileInputStream("emp.ser"))) {
    Employee e = (Employee) ois.readObject();
}
💡
Always define serialVersionUID explicitly. If not defined, JVM generates one based on class structure — changing the class will break deserialization of old data with InvalidClassException.

Generics

Generics provide compile-time type safety. Without generics, any type can be added to a collection — a runtime risk.

Java — Generics & Wildcards
// Generic method
public static <T extends Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) > 0 ? a : b;
}

// Wildcards
void printList(List<?> list)              // unbounded — any type
void sumList(List<? extends Number> list)  // upper-bounded — read only
void addNums(List<? super Integer> list)   // lower-bounded — write friendly

// PECS: Producer Extends, Consumer Super
💡
Type Erasure: Generic type info is removed at compile time. At runtime, List<String> and List<Integer> are both just List. This is why you can't do new T() or instanceof List<String>.

Immutable Class

Java — Immutable Class
public final class Employee {          // 1. final class
    private final String name;           // 2. private final fields
    private final Date joiningDate;      // mutable field!
    private final List<String> skills;   // mutable field!

    public Employee(String name, Date date, List<String> skills) {
        this.name = name;
        this.joiningDate = new Date(date.getTime());         // 3. deep copy in
        this.skills = new ArrayList<>(skills);              // 3. deep copy in
    }

    public String getName() { return name; }               // no setters
    public Date getJoiningDate() {
        return new Date(joiningDate.getTime());              // 4. defensive copy out
    }
    public List<String> getSkills() {
        return Collections.unmodifiableList(skills);         // 4. defensive copy out
    }
}

Rules: (1) final class, (2) all fields private final, (3) no setters, (4) deep copy mutable fields in constructor AND in getters.

Design Patterns

Java — Singleton (Thread-Safe)
// Double-checked locking — most efficient thread-safe singleton
public class Singleton {
    private static volatile Singleton instance;  // volatile is critical!

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}

// Enum Singleton — simplest, serialization-safe, reflection-safe
public enum DatabaseConnection {
    INSTANCE;
    public void connect() { /* ... */ }
}

Java Records (Java 16+)

Compact, immutable data class. Auto-generates constructor, getters, equals(), hashCode(), toString().

Java — Records
// One line replaces 30+ lines of boilerplate!
public record Employee(int id, String name, double salary) { }

// Custom compact constructor for validation
public record Person(String name, int age) {
    public Person {  // compact constructor
        if (age < 0) throw new IllegalArgumentException("Age cannot be negative");
        name = name.trim();  // can transform components
    }
}

Employee e = new Employee(1, "Alice", 50000);
e.name();    // accessor (not getName() — just name())
e.salary();  // all fields are implicitly final
💡
Records cannot extend other classes (implicitly extend Record). All fields are implicitly private final. Best for DTOs, response objects, value objects. Can implement interfaces.

Sealed Classes (Java 17)

Sealed classes restrict which classes can extend or implement them. Used with permits keyword.

Java — Sealed Classes
public sealed class Shape permits Circle, Rectangle, Triangle { }

public final class Circle extends Shape { double radius; }
public non-sealed class Rectangle extends Shape { }  // open for extension
public sealed class Triangle extends Shape permits RightTriangle { }

// Pattern matching with sealed classes — exhaustive switch
double area = switch (shape) {
    case Circle c    -> Math.PI * c.radius * c.radius;
    case Rectangle r -> r.width * r.height;
    case Triangle t  -> 0.5 * t.base * t.height;
};  // no default needed — compiler knows all subtypes!

Tricky Interview Edge Cases

== vs equals() — == checks reference; .equals() checks content. For strings, always use .equals().
Same hashCode ≠ same object — same hashCode means same bucket only. equals() confirms true equality.
Mutable HashMap key — if key mutated after insertion, value becomes unretrievable (wrong bucket). Use immutable keys always.
finally can override return — if finally has a return, it overrides the one in try. Never do this.
sleep() vs wait() — sleep() holds lock; wait() releases lock. wait() must be inside synchronized.
Integer cache trap — Integer a = 127 cached; Integer a = 128 creates new object. Use .equals().
String a = "abc" vs new String("abc") — literal reuses pool; new String() always creates heap object.
Constructors not inherited — use super() to call parent constructor. Must be first statement.
static methods not overridden — they are hidden, not overridden. No runtime polymorphism for static.
Java is pass-by-value — for objects, the reference value is copied. Object state can change, but reassigning the param does nothing.
Catching Error — technically possible but bad practice. OutOfMemoryError is a JVM-level problem.
Runnable over Thread — Java has no multiple inheritance. Runnable keeps your class free to extend another class.
transient + static — both skip serialization, but for different reasons: transient = explicit exclusion; static = belongs to class, not object.
volatile ≠ atomic — volatile ensures visibility but not atomicity. i++ on volatile is still not thread-safe.
Override both hashCode + equals — breaking the contract: two equal objects may end up in different buckets and HashMap treats them as different.
ArrayList.remove(int) vs remove(Object) — remove(1) removes by index; remove(Integer.valueOf(1)) removes by value.
