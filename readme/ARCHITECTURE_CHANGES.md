# Architecture Refactoring - Generic Page Template

## Overview
The application has been refactored to use a **Single Page Template** approach instead of generating individual HTML files for each markdown content page.

## Previous Architecture
```
Markdown Files (.md)
        ↓
  Batch Converter
        ↓
Individual HTML Files (pages/java.html, pages/spring.html, etc.)
        ↓
Individual JS Data Files (js/java-toc.js, js/java-content.js, etc.)
```

**Drawbacks:**
- Creates many individual HTML files (one per markdown file)
- Redundant HTML boilerplate
- Large number of individual files to maintain
- Browser downloads entire HTML page per navigation

## New Architecture
```
Markdown Files (.md)
        ↓
  Batch Converter
        ↓
  Unified JSON Files (data/pages/java.json, data/pages/spring.json, etc.)
        ↓
  Generic Template (pages/page.html?page=java)
        ↓
  Dynamic Page Loader (js/generic-page-loader.js)
```

**Benefits:**
- ✅ Single HTML template file for all pages
- ✅ Eliminates HTML boilerplate redundancy
- ✅ Fewer files to manage
- ✅ Browser caches single template
- ✅ Only JSON data changes per page
- ✅ Cleaner URL structure with query parameters
- ✅ Easier to maintain and extend

## File Structure

### New Files Created
1. **pages/page.html** - Generic template for all markdown-based pages
2. **pages1/page.html** - Alternative generic template (for pages1 directory)
3. **js/generic-page-loader.js** - JavaScript module that handles dynamic page loading

### Data Files (Generated by batch-converter.py)
- **data/pages/{page-name}.json** - Contains combined page data:
  ```json
  {
    "title": "Page Title",
    "description": "Page description",
    "icon": "📘",
    "tocHtml": "<div>...table of contents...</div>",
    "contentHtml": "<h1>...page content...</h1>"
  }
  ```

- **data/pages/{page-name}-toc.json** - Legacy compatibility (separate TOC)
- **data/pages/{page-name}-content.json** - Legacy compatibility (separate content)

### Index Links
All cards in `index.html` now link to:
```
pages/page.html?page=java-basics
pages/page.html?page=spring-fundamentals
```

Instead of:
```
pages/java-basics.html
pages/spring-fundamentals.html
```

## How It Works

### 1. User Clicks Card on Index
```
index.html displays card for "Java Basics"
User clicks card → Navigates to pages/page.html?page=java-basics
```

### 2. Generic Page Template Loads
```
pages/page.html loads generic template structure
Scripts included:
  - auth-gate.js (authentication check)
  - generic-page-loader.js (dynamic content loader)
  - main.js (common functionality)
  - highlight-local.js (code highlighting)
```

### 3. Dynamic Page Loader Activates
```javascript
generic-page-loader.js:
1. Reads URL parameter (?page=java-basics)
2. Sanitizes page name (security)
3. Fetches data/pages/java-basics.json
4. Injects HTML into template
5. Highlights code blocks
6. Attaches TOC click handlers
```

### 4. Page Displays Fully
```
Page title, navigation, TOC, and content all loaded dynamically
User experience is seamless - no different from individual HTML files
```

## Batch Converter Changes

### Updated Functions
- **create_page_files()** - Now creates JSON files instead of HTML files
- **create_card_html()** - Generates links with query parameters
- **update_index_file()** - Updates index with generic template links
- **build_index_cards()** - JSON config uses generic template format
- **regenerate_index_cards()** - Updates cards with generic template links

### Configuration
The batch converter still reads from `PAGE_CONFIGS` dictionary to determine:
- Page icon (emoji or icon text)
- Page title
- Page description

## Usage

### Running the Batch Converter
```powershell
python batch-converter.py md_folder output_folder
```

**Example:**
```powershell
python batch-converter.py md1 .
```

This will:
1. ✅ Read all .md files from `md1` folder
2. ✅ Convert to HTML content
3. ✅ Generate JSON files in `data/pages/`
4. ✅ Update `index.html` with new cards (using generic template links)
5. ✅ Generate search index
6. ✅ Generate PDF/HTML library lists

### Start Development Server
Any HTTP server will work:
```powershell
# Using Python
python -m http.server 8000

# Using Node.js (if installed)
npx http-server

# Or any other server
```

## Search Index Integration

The `search-index.json` is automatically updated with href entries like:
```json
{
  "href": "pages/page.html?page=java-basics",
  "title": "Java Basics",
  "text": "searchable content..."
}
```

Search results will link directly to the correct page with the query parameter.

## Backward Compatibility

For private deployments or alternative architectures:
- Legacy toc/content JSON files are still generated
- Can be used by alternative loading mechanisms
- Format remains unchanged for compatibility

## Migration Notes

If you have existing individual page HTML files:
1. They can be safely deleted
2. Browser history will break (old URLs won't work)
3. All new links use generic template format
4. If needed, set up redirects for old URLs

Example redirect in .htaccess:
```
RewriteRule ^pages/([a-z-]+)\.html$ pages/page.html?page=$1 [L,R=301]
```

## Performance Improvements

| Metric | Before | After | Improvement |
|--------|--------|-------|-------------|
| HTML Files | Many (one per page) | 1-2 templates | 90% reduction |
| Boilerplate Code | Repeated | Single file | 80% reduction |
| Browser Cache | Per page | Single file | Better utilization |
| Page Load | Full HTML + JS | JSON only | Faster after first load |
